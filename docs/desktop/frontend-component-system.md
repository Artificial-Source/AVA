## Product and ownership boundaries

- Keep the connected neutral shell, sidebar-only Projects/Pinned/Recent navigation
  and first-in-rail show/hide control. The latest mock-only revision removes
  the workspace top bar. The latest title correction places one current title at
  the chat canvas's top-left, without a project subtitle or duplicate sidebar heading.
  The attached right sidebar now has one dedicated Context page—not repeated details
  across Agents/Changes—and a composer meter; child Back remains available.
  No full IDE, replacement full-width toolbar or dashboard cards.
- Keep only Working's cycling icon. The user rejected the text glow and icon halo.
  Add short, restrained open/close/switch feedback and faint neutral sidebar material
  movement; no bounce, flashing, neon, wallpaper or new reference colors.
- Right-sidebar details need clear typography and reachable controls, including
  short/narrow layouts. Parent metadata remains parent-owned during child inspection.
  Ultrawide adds room around bounded reading content, not stretched prose:
  transcript and composer remain at most 780px.
- Design-system components own presentation, keyboard behavior and motion.
  Controlled chat widgets receive view models and emit explicit UI intents.
  Preview adapters/catalog fixtures own invented data and local state.
- The backend remains authority for permissions, resolvers, run settlement, sessions,
  provider data, process execution and resource ownership. A UI callback is not a
  grant, RPC reply or execution command. `PreviewState` is not a client store.
- No runtime/build dependency, animation library, router, thick store, Storybook,
  copied reference code/assets/fonts or production transport is selected here.

## Selected component foundation

Implemented under `apps/desktop-preview/src/`: `ui/` owns native Button/IconButton,
Surface, Status, Disclosure, Presence and reduced-motion foundations; `chat/contracts.ts`
owns readonly discriminated view models; `chat/widgets/` owns the seven controlled
widgets below; `catalog/` owns invented cases. `main.tsx` lazy-loads the separate
`?view=components` route. Existing Conversation/ToolActivity/Composer/ChangeReview
components adapt preview fixtures to shared widgets. These are experimental **UI
models**, not RPC schemas; widgets do not import fixture/reducer state or arbitrary
backend JSON.

| Layer | Component responsibility | Required examples/behavior |
| --- | --- | --- |
| Foundations | Neutral semantic colors/spacing/type/radius, short motion tokens, native Button/Surface/Disclosure/Presence/status rendering | Focus-visible, disabled, empty, expanded/collapsed, immediate inert exit, rapid reopen, reduced motion, opaque material |
| Turns | `MessageTurn` | Streaming vs committed, partial canceled/failed text, empty streaming, safe markdown/code; never auto-generate output |
| Tools | `ToolActivityGroup` | Queued/running/completed/failed/canceled, output disclosure, explicit truncation/absent output, stable IDs/order; no invented percentage |
| Permission | `PermissionCard` | Explicit allow/deny; session choice only if supplied capability permits it; pending/submitted/error/stale/closed, no default allow or duplicate intent |
| Question | `QuestionCard` | Single/multiple choices, custom answer only when allowed, secret input masked if supported, submit/cancel, invalid/stale/pending cases; no secret echo |
| Run notices | `RunNotice` | Stable code and generic unknown-code fallback, supplied attempt/cause, cancellation requested vs completed, optional explicit retry intent only |
| Composer | `ChatComposer` plus preview adapter | Draft, model/mode, context references, expansion and local Send/Stop callbacks; preserve IME/keyboard/focus and per-chat values |
| Change review | `ChangeReviewView` | Loading, empty, error, ready and stale-last-content; file disclosures, no mutation/Git intent |
| Catalog | Separately reachable fixture page | Label all examples/local actions as simulated; reset local state; no main-chat extra toolbar; lazy load to keep initial bundle bounded |

Existing project navigation, first-party model marks, safe markdown/highlighting,
read-only child fixture inspection and bounded composer remain useful foundations.
A widget gallery is coverage evidence—not approval of every possible feature.
Permission/question cards validate caller-supplied UI ID/version/capabilities and
answers; their mounted guard suppresses duplicate intents for an ID/version.
**It is not durable exactly-once delivery:** the host must retain authoritative
pending/settled state across unmounts. Secret inputs are masked; catalog receipts
never echo answers or claim policy/settlement/execution success. Unsupported question
placement/modes fail closed; modal/paged flows remain separately scoped.

## AVA adapter readiness: what is still missing

Authority comes from the [desktop architecture](architecture.md) and
[current RPC protocol](../rpc-protocol.md), not competitor behavior or fixture types.

| Public AVA surface | UI foundation | Remaining before real connection |
| --- | --- | --- |
| Correlated message lifecycle / `message_update` | Turn/tool widgets | Host/session/run routing, ordered reducer/adapters, admission/terminal semantics, cancellation, reconnect/replay and long-history policy |
| `tool_start` / `tool_progress` / `tool_result` | Tool activity states | Backend correlation/output sanitization and optional timeline handling; no mock schema wired directly |
| `permission_requested` | Permission presentation | Backend-owned resolver ID, effective scopes, exact-once bridge, deny-on-disconnect/stale handling; session scope only if available; backend hard denies unchanged |
| `question_requested` | Question form | Backend options/flags, validated answer mapping, opaque resolver correlation and cancellation semantics; unsupported flags fail closed rather than invented behavior |
| In-run errors/retry/`done`/`canceled` | Run notices | Stable `error.code` mapping and unknown/additive fallback; terminal settlement and recovery remain backend-owned |
| Model/mode metadata | Controlled composer | Real catalog/availability and provider identity mapping; first-party fictional marks are not provider logos |
| Image input metadata | Context/reference display | Host image admission/session ownership; maximum 16 PNG/JPEG/WebP/GIF and native dialog/process boundary. Not generic path upload or image generation |
| Public job list/status/result/control | Existing roster presentation | Real owner/run-safe job adapter and labels available from public fields only. Interactive title/type metadata must not be inferred |
| Child conversation | Existing read-only invented child view | **No public child-transcript RPC exists.** Separate backend/transport work is required; no private JSONL/session-path shortcut |
| Changes | Read-only examples | Authoritative change source/ownership, stale semantics and host resource mapping; no Git or filesystem authority in renderer |

Callback receipt in a catalog must say only that a **local fixture intent** was
received. It must never announce that a real permission was granted, resolver
settled, retry admitted, job stopped or backend command executed.

## Acceptance and exclusions

Each implemented reusable widget needs controlled-prop tests, keyboard/form/focus
coverage, safe escaped content, invalid/empty/pending/stale cases and explicit
callback behavior. Motion must keep exiting content inert/unreachable, cancel stale
completion on rapid toggles, clean up listeners/timers, and honor reduced motion.
Normal browser checks must cover desktop/laptop/narrow/ultrawide, actual opening and
closing motion, no overflow, finite base contrast and loopback-only requests.

Current implementation/validation remains recorded in [the prototype record](react-prototype.md).
These checks do not certify every assistive technology/state, GPU performance,
long-history scalability, Electron/native behavior, packaging/licenses/SBOM or
production accessibility. Light/system design, real integration, Git/worktrees,
extensions/marketplace, terminal/editor, account/auth/microphone/image generation,
private reasoning/tool streams and full IDE behavior remain separately scoped.
