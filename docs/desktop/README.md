## Agreed desktop v1 scope

The user approved a **focused coding-agent app**, not a full IDE at launch:

- Workspace, session, and model selection.
- Streaming chat, tool activity, and change review.
- Independent chats running in parallel, including multiple chats on the same
  project; switching the viewed chat must not stop work already in progress.
- Optional Git worktrees, explicitly enabled by the user for Git projects.
- One default multi-project window, without restricting users to one window;
  optional additional windows support project focus or other monitors.
- A full project/chat sidebar with running and attention state. **No horizontal
  chat tabs.** Optional user-pinned chats and recent-chat shortcuts belong below
  Projects in the sidebar and may span projects. This supersedes the earlier
  approved horizontal chat working-set proposal after prototype feedback.
- Permission prompts, structured questions, and explicit cancellation.

The approved [navigation direction](window-navigation-research.md#approved-navigation-direction)
sets the multi-project default, optional windows, and sidebar-only navigation
with optional Pinned/Recent shortcuts. The [T3 Code reference](desktop-inspiration.md#t3-code-project-and-thread-organization)
is the closest verified match to the user's Theo/T3 example. Exact project
identity/grouping, session routing, and worktree creation/selection/lifecycle
ownership remain open.

Removing a sidebar pin/recent shortcut or switching chats is navigation, not
cancel, delete, or archive; reopening the same existing chat must not duplicate
its agent/run.
Window-close and application-quit behavior remain open.

Chats share the project working copy by default; users are responsible for
avoiding conflicting tasks or file changes. Optional user-enabled Git worktrees
provide separate working copies, not conflict-free integration. Backend
permission, containment, and session checks still apply. Worktrees are never
enabled automatically and are not a security sandbox.

Built-in editors, terminals, cloud sync, and complex settings are deferred.
This is feature-level product scope, not app implementation or final visual
approval, nor a change to the first official host release. Initial concepts
are separately authorized; parallel chats are a v1 requirement, not a later
enhancement.

## Current visual direction

The first flat light/dark SVGs were rejected. The user then liked Astra max's
premium minimalist liquid-glass study and authorized a separate **React/TypeScript
UI-only port with mock data**, explicitly requesting Astra at max reasoning for
code and design. The first React pass joined the shell but still used blue-toned
surfaces, horizontal tabs, and a full-width glass composer footer.

The latest prototype feedback supersedes those choices:

- **No horizontal tabs or empty pinned-chat strip.** Full Projects navigation,
  with optional Pinned/Recent shortcuts below Projects in the sidebar.
- A bounded, inset composer inside the opaque reading canvas, not a full-width
  colored footer. Remove the persistent preview helper/shortcut row.
- Remove the bottom sidebar utility bar and noisy developer-style chrome.
- Use elegant **neutral black/white/grays**, with subtle neutral glass treatment,
  rather than the prior mineral-blue palette.

The connected root/sidebar, readable conversation spacing, and no staging
wallpaper or background gutters remain. On 2026-10-05 the user gave enthusiastic
positive feedback on this monochrome revision, then requested
[right-sidebar/status/composer research](sidebar-activity-research.md). Supplied
references are **layout only**, not a request for their colors. The user then
authorized a mock-only Agents/Changes rail, read-only child-conversation
inspection, compact leading statuses, and richer composer controls, again owned
by **Astra at max reasoning**. Git/GitHub/images/extensions remain future modules,
not authorization for live integrations, a full IDE, or dead placeholder buttons.
Matching light design and production qualification remain separate.

The prototype lives separately in `apps/desktop-preview/`. Pinned prototype
dependencies may be installed there after verification; the legacy client is
not replaced. Backend integration, provider calls, session/filesystem access,
and full-client production adoption remain outside this authorization.

Light/dark system themes remain the intended theme behavior. Final refined
layouts and production token/font choices remain to be settled.
Translucent navigation/control surfaces must not compromise conversation
legibility; status accents still require clear labels/icons and a static
reduced-motion fallback. No Apple fonts,
SF Symbols, or faux macOS window controls are selected. Other approved product
scope and library families are unchanged.
