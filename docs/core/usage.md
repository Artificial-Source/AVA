# AVA Usage

This is the current interface guide. Use [tools.md](tools.md) for the complete built-in model-tool catalog (distinct from slash commands), [environment-variables.md](environment-variables.md) for process inputs, and [troubleshooting.md](../operations/troubleshooting.md) when a workflow fails.

## Starting AVA

```sh
ava
ava auth login
ava login anthropic
ava auth login moonshot --api-key
ava connect openai
ava connect openai --headless-oauth
ava connect kimi --api-key-env KIMI_API_KEY
printf '%s\n' "$OPENAI_API_KEY" | ava connect openai --api-key-stdin
printf '%s\n' "$ANTHROPIC_API_KEY" | ava connect anthropic --api-key-stdin
ava connect moonshot --api-key-env MOONSHOT_API_KEY
ava --mode plan
ava --continue
ava --resume
ava --session <id-or-prefix>
ava --session-id <id-or-prefix>
ava --fork <id-or-prefix>
ava --name "release audit"
ava --session-dir ./ava-sessions
ava --no-session
ava --offline
ava --thinking high
ava --agent reviewer "review this repo"
ava --print "summarize this repo"
ava --rpc
ava --acp
ava --line-shell
ava doctor --json
ava --trace --rpc
ava support export
```

`--continue` resumes the newest session for the current workspace; `--resume` and `-r` are Pi-compatible aliases. `--session` resumes an exact ID or a unique prefix; `--session-id` is a Pi-compatible alias. `--fork` creates a new branch from an exact ID or unique prefix. `--name` sets the startup session display name, and `--session-dir` selects a custom session storage directory for this process. `--no-session` runs with in-memory history and does not create a resumable JSONL session; it cannot be combined with `--continue`/`--resume`, `--session`/`--session-id`, or `--fork`. `--thinking off|<level>` sets the startup reasoning selection for the active model; `off` clears explicit reasoning, while other values must be listed in the active model's reasoning levels. On exit, AVA prints the command needed to resume the current session unless sessionless mode is active.

Choose the interface by contract: the TUI is the interactive terminal UI; `--line-shell` is the bounded line-oriented interactive text frontend; print mode is one-shot text/JSON automation; `--rpc` is AVA's proprietary JSONL subprocess API for automation/custom clients; and `--acp` is the separate stable ACP v1 JSON-RPC 2.0 stdio endpoint for specifically configured editor/IDE clients. `--line-shell` is incompatible with print, RPC, and ACP modes. AVA RPC is not ACP, generic JSON-RPC, or Pi RPC. Pi RPC remains reference behavior for subprocess embedding, custom UI, automation, and testing rather than AVA's editor-interoperability contract. See [`rpc-protocol.md`](../rpc-protocol.md) for RPC and [`acp.md`](../acp.md) for exact client setup, evidence labels, and limits.

## Diagnostics And Support

Use `ava doctor` for a passive human-readable readiness report or `ava doctor --json` for automation. Doctor does not call providers, read credential values, launch integrations, mutate configuration, create sessions, or write diagnostic state. Add `--trace` to a normal TUI, print, RPC, or ACP invocation to create one private bounded metadata trace; tracing is disabled by default. `ava support export` creates a new sanitized local JSON artifact and prints its exact path. The export contains generated readiness/status facts, typed counters, and a typed last-failure record—not trace lines, sessions, prompts, reasoning, commands, paths, configuration contents, identities, credentials, raw errors, stderr, or remote payloads. AVA never uploads it. See [`diagnostics.md`](../operations/diagnostics.md) for storage, limits, privacy guarantees, and libcwd's separate developer-debug role.

## Modes

- Build mode: normal coding mode. Workspace edits are allowed unless a path or command is risky.
- Plan mode: read/search is allowed, but source-code mutation is denied. Planning markdown may be written.

Press Tab in the TUI to accept an open autocomplete suggestion. Slash command names and non-file argument completions use Pi-style fuzzy matching, so `/gp` can find `/grep` and model searches such as `/models sonnet` or `/models 4sonnet` can find a Sonnet model. Model and named-session suggestions lead with their human label while retaining the canonical `provider/model` or exact session id for insertion. Permission-rule, job, and keybinding argument completions likewise lead with human permission summaries, job labels, or keybinding help labels while keeping exact `permrule_…`, `job_id`, and action ids as the hidden insertion values; labels never replace control authority, and the palette does not show a visual `[complete]` marker. When no palette is open, Tab first tries file-path completion for the active token, including an empty token after Space, a bare token, or a slash-command argument when command-specific completions do not match; a single enabled result inserts, multiple results open a palette, and a disabled result remains visible but is not inserted. If no path candidates match, Tab toggles mode. `/mode` also switches modes.

Model selection takes effect immediately between turns and is not rejected because of earlier session content. For every provider request, AVA reprojects a copy of history for the selected target: exact source provider/model/API/reasoning matches may retain native replay, while a mismatch or missing provenance uses portable visible text, drops hidden reasoning and provider-private metadata, gives complete tool pairs request-local IDs (or labelled text for a no-tools model), and replaces incompatible historical images with MIME-and-size placeholders. The persisted session remains append-only and unchanged by this request-time projection. Selection is immediate, but the next request still fails closed if committed v4 output is malformed or a committed v4 function call lacks its exact bound tool result; portable projection does not repair invalid session history.

## TUI Layout

The interactive TUI runs on wide-character ncurses (`ncursesw`) for terminal mode, keyboard/mouse input, resize handling, and screen drawing. The layout is composer-first:

- There is no persistent top header or horizontal transcript/composer separator. Existing transcript-local prefixes carry message meaning inside one shared canvas; ordinary conversation and composer content is capped at 120 columns and centered on wider terminals. The automatic ownership rail keeps its established zero-origin main-pane width, and the `/sidebar` drawer uses the full terminal.
- The transcript renders user, assistant, inline thinking, tool, system, and error entries with distinct text markers. At widths of at least 44 columns and heights above 12 rows, one blank row separates logical user, assistant-flow, error, and system/audit groups; consecutive thinking, assistant, and tool parts remain together. Narrow and short layouts remove those inter-group blanks. Consecutive context-gathering tools retain one shared heading rather than gaining per-tool separators; queue, delivery, and audit receipts are System entries while the active queue dock remains primary; and no trailing transcript blank is emitted. Completed long thinking blocks default to a bounded preview of at most 12 rendered rows (first 11 content rows plus a dim/plain `… N lines hidden` footer counted from the same width-dependent line vector); short thinking renders fully with no chrome. Live append-only pending reasoning stays fully expanded while streaming. Click the `Thinking:` header, or run `/thinking details`, to expand or collapse one completed boundable block; bare `/thinking` still toggles global thinking visibility. The configurable `thinking_toggle` action remains available but is unbound by default. Expansion is presentation-only, independent per duplicate block, carried across active-run snapshot rebuilds by transcript index ownership, and not persisted across process or session reload. Transcript search indexes only currently rendered thinking lines, so a hidden tail is not matchable until expanded.
- Tool activity defaults to **Rich** cards: each card presents a human-readable call, a sanitized tool-specific output preview (about 20 lines for shell/search/list tools, 10 for read/write/edit tools, and 12 for other tools), and explicit hidden/truncated/spill/diff information when available. These are previews, not claims that all tool output is shown. `/details compact` selects a single fitted summary row; `/details rich` restores the default; `/details expanded` shows retained detail up to a defensive display cap. Bare `/details` and Ctrl+O toggle Rich and Expanded, while `/tool [query]` toggles only the matching card. Routine permission/question receipts and resolver identities remain internal audit/sidebar data: ordinary cards and `/copy tool` omit them. Denied cards use a human-readable reason. When an immediately following assistant message exactly repeats a nonempty tool result, only the tool's visual result phrase is omitted, so the assistant answer remains present exactly once without changing stored history.
- The automatic side rail is progressive rather than permanently occupying ordinary terminals. It appears from `144x16` while running activity or modified files make it actionable, and from `176x16` for idle session/context metadata; permission prompts, questions, and selectors suppress it and use the shared centered canvas. A single one-cell dim divider separates the rail from the zero-origin main pane, and rail content has a two-cell local inset. Its primary `Session` title and compact mode/provider/model metadata remain visible while disclosed; optional groups show only currently running `Activity`, nonempty `Modified Files`, and known `Context` values (branch, reasoning, non-unknown token usage/pressure, and context-source count, including zero). Empty, idle, completed, no-change, and unknown placeholders are omitted, as are raw session id/path/entry count, workspace, and version. The rail remains bounded to 38 columns; outside those conditions terminals wider than 120 columns center the width-limited transcript/composer canvas, while exact `/sidebar` keeps complete context reachable at full terminal width.
- Exact `/sidebar` opens the complete semantic data in a temporary full-width `Session overview` drawer at any terminal size and suppresses the automatic rail while open. Unlike the curated rail, the drawer retains activity history, empty/unknown states, session id/path/entry count, workspace, usage/context detail, and version. Page Up/Page Down, Home/End, and the mouse wheel navigate the wrapped drawer; Esc closes it and restores composer focus without changing the draft. Permission prompts, docked or modal questions, and select-list views take focus and suppress the drawer until they resolve.
- Normal startup reserves no persistent overview rows: the quiet composer footer remains the home for ordinary mode/model/context essentials, and the path-free startup resources stay available on demand. Exact `/overview` (or an explicitly bound `app.overview.toggle` action, unbound by default) opens a bounded read-only select-list built only from already-loaded runtime state: mode/model, trust, instruction/skill/plugin counts and safe names, theme, and key hints. Session titles, raw session ids, and other free-form/prompt-derived session text are omitted entirely. Builder input is hard-capped (first 64 context/freshness sources): the instruction-source total stays exact from the already-loaded span size, while capped per-group aggregates and plugin-resource failure counts render as lower bounds (`N+`, including truthful `0+` when shown). Named skill/prompt/plugin lists keep their own truncation markers. It never appends session JSONL, calls providers, reopens resource paths, or shows credentials, prompt contents, private leaves, or MCP/LSP enablement claims that are not already retained path-free.
- The bottom composer uses a quiet two-row idle/single-line block: one input row above one footer row, each beginning with the `│  ` boundary and gutter and with no prompt glyph. Ordinary draft, status, and footer dock rows inherit the terminal-default/`screenBg` canvas like transcript chat; elevated `composerBg` remains for palettes, selectors, and other panel surfaces. Multiline drafts grow by visible wrapped input lines plus one footer, bounded to two through eight rows. The footer is not expanded by the shell: it contains only the active model, active conversation-context usage as `ctx count (percent)` (for example `ctx 150.3k (55.3%)`, or an estimated `ctx ~count` such as `ctx ~150.3k` when the model window is unknown), and a fixed four-cell signal meter while processing. `/context` and the sidebar retain loaded instruction-source counts.
- In the nonmodal dock, composer space and any permission/question reservation take precedence. Question rows use a distinct background (custom `questionBg`, falling back to `composerBg`), wrap the question within the bounded dock, and preserve a selectable answer and cancellation action on short terminals. AVA reserves up to three error-category status-alert lines, plus one active-run contextual row when room permits, before assigning the remaining budget to slash/file/path palettes, queued messages, and pending attachments. The visual order remains palette, queue, attachment, contextual hint, alert, permission/question, composer, so an admitted alert remains immediately next to the composer. During an active run only, a muted composer-bound row shows `Esc stop` and either invites a follow-up or uses the configured queue/follow-up/dequeue keys; when the backend reports allowlisted running `retry` or `compaction` activity it can also show that compact status (including a retry countdown). It disappears while idle or while a palette/prompt/modal owns the rows. The permanent footer stays model, `ctx count (percent)` or `ctx ~count`, and the four-cell signal meter while active.
- Enter submits; Shift+Enter or Ctrl+Enter inserts a newline, and Alt+Enter submits while idle or queues a follow-up during an active assistant/compact run. Arrow Up/Down scroll transcript history without moving or replacing the composer draft; defaults are `message_prev`=Alt+K, `message_next`=Alt+J, and `jump_to_bottom`=Ctrl+End. Alt+J/Alt+K can be rebound as editor aliases only by overriding those defaults. `history_prev`, `history_next`, `cursor_up`, and `cursor_down` remain configurable but are unbound by default, Home/Ctrl+A and End/Ctrl+E move to the current line boundary, Ctrl+Left/Right, Alt+Left/Right, or Alt+B/F move by word-like segment with punctuation boundaries such as `/`, `.`, and `:` kept distinct, Ctrl+] jumps forward to the next typed character and Ctrl+Alt+] jumps backward, Delete or Ctrl+D removes the character after the cursor while the draft has text, Ctrl+W or Alt+Backspace deletes the previous word segment, Alt+D or Alt+Delete deletes the next word segment, Ctrl+U deletes to the current line start, Ctrl+K deletes to line end and joins the next line when already at line end, Page Up/Page Down or mouse wheel scroll transcript history even when the pointer is over the composer (transcript wheel accepts three rendered rows per event, coalesces same-direction bursts at 40ms, and applies an opposite-direction event immediately; selectors, questions, the sidebar drawer, and selection-edge autoscroll stay one row per accepted event), mouse clicks select visible slash-palette, file-reference, path-completion, or select-list modal rows when the terminal reports coordinates, and an unmodified left-button drag selects rendered transcript text for bounded OSC 52 copy through `copy_selection` (Ctrl+C when the draft is empty). Shift-modified mouse remains available for terminal-native selection. A stationary click still toggles tool/thinking headers, while movement from a header starts selection at the original press endpoint. Composer motion and delete operate on compact terminal text clusters (base+marks, regional-indicator pairs, emoji modifiers, and ZWJ emoji sequences; not full UAX #29). Contiguous ordinary typing forms one undo group; directional consecutive kills accumulate on the same kill-ring entry. Ctrl+- undoes the last composer edit, Ctrl+Z suspends AVA to the shell on Unix terminals and redraws after `fg`, Ctrl+Y yanks the latest kill-ring entry, Alt+Y cycles through kill-ring entries after a yank, Ctrl+C clears a non-empty composer draft and exits only when the draft is empty, Ctrl+D exits the current TUI loop when the composer is empty, Ctrl+G opens the draft in `$VISUAL` or `$EDITOR` and replaces the composer with the saved file when the editor exits successfully, Ctrl+V imports a clipboard image as a pending attachment when a supported helper is available, Ctrl+L opens the model selector between turns, Ctrl+P cycles to the next configured or scoped enabled model between turns, Shift+Ctrl+P cycles to the previous model when the terminal reports that enhanced key sequence, Shift+Tab cycles backend-declared reasoning levels for the active model when available, Ctrl+T opens the policy-resolved thinking-mode selector between turns, and Esc dismisses the active palette or starts the safe clear-input flow. `/scoped-models` opens the model-cycle selector for Ctrl+P; changes apply to the running TUI immediately, and Ctrl+S persists the scoped cycle in `models.json`. While AVA is actively responding, Esc requests a cooperative stop and keeps the TUI open; stopped turns say to submit a new prompt to continue. During an active assistant or `/compact` run, typing a draft and pressing Enter or Alt+Enter queues a backend-owned follow-up turn. Typing `/steer your note` during an active run queues steering for the next safe provider boundary. Pending queued items render above the composer; `/restore` or Alt+Up restores the latest pending queued item to the draft before it starts. Stopping the active run skips pending queued items, and queue outcomes render as transcript audit entries with delivery guidance.
- Bracketed paste is enabled while the TUI is active. Pasted multi-line text is normalized into the draft instead of being treated as submitted commands, and tall drafts show a `draft +N above` indicator when earlier draft lines are hidden.

Completed assistant fenced blocks labelled `mermaid` may use the disabled-by-default bounded helper configured in `display.json`. Projection is literal and presentation-only; pending, disabled, failed, or stale work renders the original fence. The helper is application-owned, never launched by TUI renderer code, and cannot mutate transcript/session meaning. This is neither full Mermaid support nor an arbitrary extension renderer.

Plain `/copy` and F5 (`app.transcript.copyLatestAssistant`, its default binding) copy the latest completed assistant text through the bounded OSC 52 path; local failures are explicit, and a successful terminal write is reported only as a request sent rather than as clipboard delivery. Transcript drag selection also uses bounded OSC 52, supports double-click word and triple-click line selection, and shows a transient scrollbar while navigating. Previous/next user-turn navigation is available without filtering session-tree content. `app.transcript.halfPageUp` and `app.transcript.halfPageDown` are configurable and unbound by default.

`/cursor <default|block|underline|bar> [blink|steady]` controls the persisted cursor presentation. DECSCUSR is emitted only while a cursor is forced and is reset/reapplied around suspend or external-editor handoff. Direct environment-identified Alacritty sessions use a best-effort asynchronous strict DA2 version gate: versions through 0.14.0 (packed through 2401) retain conservative Kitty keyboard flags 5, while 2402 and later use flags 7. AVA skips this probe through mux paths and never blocks startup on it.

F6 (`app.prompt.stash`) stashes and clears a nonempty draft, or opens the stash selector when the draft is empty. `/stash`, `/stash pop`, and `/stash clear` expose the same process-memory stack. It holds at most 16 entries, 64 KiB expanded per entry and 256 KiB aggregate, with no eviction. Pending images cannot be stashed; restore refuses to overwrite a nonempty draft. Entries survive session transitions in the same process but not process exit.

On a fresh interactive TTY launch, AVA opens directly to the normal composer. If the selected provider has no stored or environment credential, the TUI shows ordinary disconnected auth guidance such as `! OpenAI not connected · /connect`; line-shell paths retain equivalent `/connect`/`/login`, CLI, environment-variable, and auth-file guidance. Submitting a provider prompt before connecting returns the same guidance while offline slash commands remain available. AVA has no local setup wizard and does not read, write, migrate, or delete an onboarding marker; stale marker files are ignored.

Use `/theme dark`, `/theme light`, `/theme plain`, `/theme <custom-name>`, or `/theme reset` to persist AVA's TUI display mode in `$XDG_CONFIG_HOME/ava/display.json`. The built-in dark and light palettes use neutral muted hierarchy with blue reserved for focus/actions; warning, error, and success meaning remains textually distinct rather than color-only. Custom theme files live under `$XDG_CONFIG_HOME/ava/themes/*.json` and define AVA's eight ncurses color roles without being overridden by built-in palette tuning. `/settings` opens a compact shallow selector with six destinations: Theme, Display, Model, Input, Workspace, and Tools. Root rows are label-only; each section uses concise label/value rows, and the search row appears only after typing. Theme owns built-in/custom choices and reset, while Display owns image visibility/width and thinking-block visibility. Model, Input, Workspace, and Tools route to existing selectors or draft/apply existing commands rather than duplicating backend semantics. Highlighting previewable Theme or Display rows changes presentation only; Enter confirms once through the same writers as `/theme`, `/images`, and `/image-width`. The interactive TUI automatically reloads hand-edited `display.json` and the bounded custom-theme catalog (including unconfigured previewable themes); `/reload theme` remains available for an explicit retry or diagnostic. Applied presentation reloads rebuild the active Theme or Display rows while preserving the filter query and reselecting the prior actionable row by hidden value so preview overlay and Enter stay aligned when custom themes are inserted or reordered. Theme precedence is `NO_COLOR`, then an active settings highlight preview, then `AVA_TUI_THEME=dark|light|plain`, then `display.json`/custom themes, then startup OSC 11 background detection on direct terminals (skipped under tmux), then `COLORFGBG`, then built-in dark. Built-in light/dark keep the ordinary screen canvas at the terminal-default background. Set `AVA_TUI_THEME` to override the theme for the current process, or set standard `NO_COLOR=1` to render without ANSI styling while preserving the same visible layout, modal content, and width bounds; `NO_COLOR` wins over environment, persisted, and preview theme values.

Use `/keybindings validate` directly when a validation-only check is needed.

The slash palette opens above the composer while typing `/`. Use arrows to move focus, Tab or Enter to insert the selected command or argument suggestion, and Esc to dismiss without clearing the draft. Each candidate stays one line and prioritizes its human display label or value, usage/key hint, useful description or disabled reason, then category. The selected item is visually highlighted with a `›` marker. Disabled command, file-reference, and path candidates remain visible with a reason; keyboard, Enter/Tab, and mouse acceptance beep and leave the draft unchanged. Palette display text is terminal-sanitized, while insertion keeps the canonical authoritative value (including exact rule, job, and action ids when the visible row is a human summary). Argument suggestions are only shown from backend/session data sources, such as configured models, resumable sessions with names/labels, loaded context sources, configured MCP servers, plugin metadata, permission/job/keybinding controls, and bounded workspace path candidates for `/read`, `/attach`, `/write`, `/glob`, and `/grep` include globs. Slash path candidates are relative to the current directory, skip reference-code/build/cache-heavy folders, and keep directories open for nested completion. Large bracketed pastes collapse to a visible `[paste #N ...]` marker in the composer, behave as one editable unit for character/word cursor movement and deletion, and expand back to the original pasted text when submitted.

Typing `@` in normal prompt text opens file-reference suggestions for bounded workspace-relative paths. Suggestions use case-insensitive fuzzy matching, include paths with spaces as quoted `@"path with spaces"` tokens, keep directories open for nested completion, and recognize token delimiters such as whitespace, `=`, single quotes, and prose wrappers like `(@src)` or `[@src]`. When the prompt is submitted, AVA reads each referenced file through the permissioned read path and appends bounded file content to the user message sent to the provider.

Normal prompt text opens path suggestions when the active token is path-like, such as `src/`, `./src`, `file=src/`, `path='src/`, or `path="my folder/`. Ordinary Space only inserts a trailing draft cell and never opens completion. Pressing Tab explicitly forces path suggestions for an empty token after whitespace or a bare token such as `main`, and either inserts the single match or opens a path palette for multiple matches. These completions only edit the draft text; use `@` when the file content should be attached to the provider prompt.

Use `/attach <path>` or `/image <path>` in the TUI to import a local PNG, JPEG, WebP, or GIF image into AVA-managed session attachment storage. Relative paths resolve from the current runtime directory. Press Ctrl+V to import a clipboard image through `wl-paste` or `xclip` on Linux when one of those helpers exposes a supported image MIME type; `AVA_CLIPBOARD_IMAGE_FILE=/path/to/image.png` can be used as a deterministic override for scripted terminal smoke tests. The TUI shows a pending attachment row above the composer with the image name or clipboard label, MIME type, byte count, and detected preview mode, then sends the queued image with the next normal prompt. When the active terminal supports it, AVA loads the validated session-owned image bytes and emits a row-reserved inline preview through a trusted renderer side channel; unsupported terminals, tmux/screen, and `NO_COLOR`/plain mode keep textual metadata only. Attachment imports are rejected before a provider turn starts when the source is unsupported, empty, a symlink, non-regular, or over the session attachment cap.

Project context files (`AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`, or `CLAUDE.MD`, first match per directory) still load by default, but executable or stronger model-influencing project resources are skipped until the workspace is trusted. Use `/trust status` to inspect the current decision and protected resources, `/trust project` to enable project prompt commands, project skills, project plugins, project MCP/LSP config, and project `SYSTEM.md` or `APPEND_SYSTEM.md` files for this workspace, `/trust deny` to keep them skipped, and `/trust clear` to remove this workspace's explicit decision. The TUI `/settings` Workspace view shows the same project trust state as a concise path-free modal summary (decision, resource status, protected-resource count) alongside the trust actions while still routing changes through the backend `/trust` commands; detailed protected-resource diagnostics stay with explicit `/trust status`.

Use `--system-prompt "text"` to replace the selected system prompt for the current AVA process, including built-in/provider prompt overrides and discovered `SYSTEM.md` files. Use repeated `--append-system-prompt "text"` flags to append extra instructions; when present, these CLI append values replace discovered `APPEND_SYSTEM.md` files. Loaded context, prompt commands, skills, and plugin prompt/skill resources are still appended after the CLI prompt text, and `/context` reports the CLI sources as inline.

`/connect` opens a centered provider login modal. Type to search providers, use arrows to move selection, press Enter to confirm, then choose a login method. OpenAI shows ChatGPT Pro/Plus browser OAuth, headless OAuth, and API key options; OAuth waiting modals keep the URL and `C` copy shortcut visible, and browser OAuth opens the default browser automatically. Non-OpenAI providers use API-key setup unless AVA implements a documented provider-specific login flow. `/login` is an alias. This is the intended path from disconnected `/connect` guidance to an authenticated TUI prompt.

## Permission Prompts

Interactive permission requests replace the composer with a quiet `! Permission required` approval dock. The dock follows OpenCode's plain-language shape while preserving AVA's stricter backend policy: it shows the human action, sanitized command or path summary, external-directory wording for outside-workspace targets, risk, reason, selected action, and key help. Raw request IDs and routine allow/check receipts stay out of the decision surface, ordinary tool cards, and `/copy tool`; use the explicit `/permissions audit`, `/permissions diagnose`, or `/copy permission` surfaces when audit detail is needed. File mutation prompts show a backend-provided unified diff before approval when AVA can safely compute one; otherwise the prompt falls back to the conservative summary without inventing a diff in the TUI.

- `A`: allow once
- `S`: allow for this session (shown only when the backend approves a reusable session-scoped command recipe)
- `D`: reject once
- `R`: remember the selected allow or reject action as a persistent exact-match rule when available
- `Enter` or Space: confirm the selected action
- `Esc`: reject
- Tab, Left, or Right: move selection

`Reject` is the default focused action. `A` and `D` are one-shot decisions. `S` creates an in-process, in-memory session grant for the current AVA session keyed by the tool name and typed recipe bound to the preserved logical workspace identity; it is never written to disk, it is cleared when the active session changes, and it is capped at 64 grants (fail-closed). Persistent rules resolve before this TUI-only fallback, so a matching persistent deny never falls through to a session grant. `S` is only offered when the command has a stable sealed recipe, verified containment, a non-Critical risk level, and a backend policy that permits session scope; Critical, uncontained, or unverified commands do not show it. When persistent rules are available, the dock also shows remembered `Always` allow and remembered reject rule choices; `R` toggles the selected action between one-shot and remembered. A remembered TUI choice creates an exact workspace-scoped persistent rule for the prompt fields before resolving the current prompt, and the dock shows an exact workspace rule preview (recipe display, command, path, or operation) without recipe hashes. `G` enters bounded one-shot denial guidance and forces the selected action to `Reject`; type an optional reason for the model, then Enter rejects with that guidance while Esc rejects without it. Guidance is provider-replay-only: it is injected into the provider-facing tool result and is absent from audits, events, RPC/ACP payloads, diagnostics, and debug representations. RPC clients can still attach a bounded denial `reason` to `permission_reply` for the separate denial resolution message preserved in tool results and audits. Permission decisions are recorded in the session audit trail and export when a session is active. Use `/permissions audit [query]` to inspect recent session decisions, `/permissions audit summary [query]` to group matching decisions by action, resolution, source, risk, operation, and tool, `/permissions audit show <entry_id|request_id>` to drill into a specific audit entry or request, `/permissions audit export [query]` to render matching decisions as a copyable Markdown table, `/diff [query]` to show the latest or matching unified tool diff in the TUI, `/copy permission [query]` to copy the latest or matching permission detail payload through the TUI clipboard path, `/permissions diagnose [query]` to explain recent denials with reasons and follow-up commands, and `/permissions` to list, explain, add, or remove persistent rules. RPC clients can create process-local exact-match session grants with `allow_session`; those grants are inspectable, revocable, clearable, and not persisted across restarts.

## Line Shell And Non-TTY Mode

Use `--line-shell` for AVA's bounded, sanitized, line-oriented accessibility and scrollback frontend. It bypasses ncurses, alternate-screen mode, mouse/graphics, and other full-screen protocols. Permission and question prompts use numbered choices so every flow remains ordinary text. This is a useful screen-reader-oriented surface, not broad screen-reader certification. It cannot be combined with print, RPC, or ACP mode.

When stdin/stdout are not both terminals and no headless mode is selected, AVA selects the same line shell automatically. This keeps tests and scripts non-full-screen.

```sh
ava --line-shell
printf '/sessions\n/quit\n' | ava --continue
```

## Headless Modes

Use print mode for one-shot automation:

```sh
ava "summarize this repo"
ava summarize this repo
ava --no-session "summarize without saving history"
ava --name "release audit" "audit the release notes"
ava --fork <id-or-prefix> --name "alternate fix" "try a smaller patch"
ava --session-dir ./tmp-sessions --print "use an isolated session directory"
ava @README.md "summarize this file"
ava -p "@docs/notes with spaces.md" "summarize this file"
ava --print "summarize this repo"
ava --print --agent reviewer "review this repo"
printf 'summarize this repo\n' | ava --print
ava --print "summarize this repo" --json
ava --mode json "summarize this repo"
ava --tools read_file,grep "inspect files safely"
ava --tools read,grep,find,ls "inspect files with Pi-style names"
ava --no-tools --tools read_file "read only the file I name"
```

`--agent <name>` selects one configured `mode: primary` or `mode: all` definition for this invocation. It works with the interactive TUI, `--line-shell`, `--print`, and CLI `--rpc`; ACP is standalone and rejects it. The option must appear at most once and requires one name. Selection is not written to session turns or persisted as a user preference.

The resolved definition and effective tool policy remain fixed for the active runtime session, including model switches, `/reload`, and trust-prompt reloads. Session navigation/replacement carries the name and resolves it for the newly opened session. Therefore configuration or trust changes that should alter selected-agent identity or policy require a new or replaced session; there is no live picker or switching command.

Bare prompt text uses the same one-shot path as `--print`; multiple positional prompt tokens are joined with spaces. CLI `@path` text file arguments are collected separately from prompt words and expanded through the same bounded permissioned file-reference path used by the TUI. Quote the shell argument when the path contains spaces, as in `"@docs/notes with spaces.md"`. Text print mode writes final assistant text to stdout and diagnostics to stderr; when either stream is a TTY, AVA sanitizes terminal control bytes before writing model/tool text while leaving non-TTY pipes raw for automation. JSON print mode writes newline-delimited runtime events to stdout and can be selected with `--json`, `--output json`, or Pi-compatible `--mode json`. `--mode text` is a compatibility alias for one-shot text print mode. `--thinking off|<level>` works in interactive, print, and RPC startup: `off` clears explicit reasoning, and other values use the same active-model reasoning-level validation as RPC `set_reasoning` (for example `low`, `medium`, `high`, or `xhigh` on the default GPT-5.5 model). Prompt turns require configured auth for the active provider unless `--offline` stops the provider call before credential resolution.

Use `--name` with interactive, print, or RPC startup to set the display name before the first turn. Use `--fork <id-or-prefix>` to start a new persisted branch from an existing session; it can be combined with `--name` but not with `--session`, `--session-id`, `--continue`, `--resume`, or `--no-session`. `--session-id <id-or-prefix>` is a Pi-compatible alias for `--session <id-or-prefix>`, and `--resume`/`-r` are aliases for `--continue`/`-c`. Use `--session-dir <dir>` when a process should read and write sessions somewhere other than the default XDG state directory. Use `--no-session` when the current process should not write a resumable session file. Session data remains available to in-process commands while AVA is running, but `--continue`, `--resume`, `--session`, `--session-id`, `--fork`, and persisted session listings ignore it.

Tool visibility is process-local and applies to interactive, print, and RPC sessions. Use `--tools name[,name...]` to advertise and dispatch only selected tools, `--exclude-tools name[,name...]` to remove tools, `--no-builtin-tools` to hide AVA built-ins while leaving enabled plugin/MCP tools available, and `--no-tools` to hide everything unless an explicit `--tools` list re-enables names. AVA accepts native names and Pi aliases: `read` maps to `read_file`, `write` to `write_file`, `edit` to `edit_file`, `find` to `glob`, and `ls` to `list_directory`. `--exclude-tools` wins over `--tools`. These flags do not grant permissions; combine them with `--allow-tool` only when a headless visible tool should also auto-approve a matching backend permission prompt.

`--offline` applies to interactive, print, and RPC startup. It disables provider model calls for prompt turns and provider-backed compaction before credential resolution. Print prompt turns fail closed with an offline/provider-call error; RPC provider-backed requests return in-band `success:false` while local inspection and slash/RPC commands that do not need a provider remain available. `--offline` does not grant or deny tool permissions by itself and is not an OS/network sandbox; network-capable tools remain controlled by tool visibility plus permission policy.

AVA seals every local model-visible `bash` request before permission evaluation. Losslessly parsed direct commands can become recognized recipes: inspection runs automatically, while builds/tests such as CMake/CTest, Ninja/Make, package-manager scripts, and exact workspace Python/Node scripts run automatically only when verified development containment is available. Sensitive network/external-state commands ask with backend-bounded reusable scopes. Explicit user shell helpers (`/bash`, `!`, `!!`, and direct RPC commands) always select raw-shell intent, so even `git status` is Critical, prompts once, and cannot create a reusable grant. Local execution requires the `Enabled` command runtime; `Legacy` and `PromptOnly` never execute. After approval AVA opens and metadata-verifies the sealed executable, then executes that descriptor rather than its pathname. Command children use a filtered PATH and positive-list environment that excludes provider/cloud/API/token/secret variables and arbitrary inherited host state. Automatic host-user discovery is limited to a safe `~/.local/bin`; delegated execution omits it, while explicitly supplied safe PATH entries and workspace-local paths retain their generic behavior. See `docs/security/containment.md` in the source tree.

Pi's built-in tool names map to one AVA-native schema per operation: `read` -> `read_file`, `write` -> `write_file`, `edit` -> `edit_file` for one exact replacement or `apply_patch` for multi-file exact replacements, `bash` -> `bash`, `grep` -> `grep`, `find` -> `glob`, and `ls` -> `list_directory`. AVA-only model-visible tools are capability/safety extensions: `webfetch` and `websearch` require explicit network permission, `skill` only reads bounded configured skill resources, `task` runs a configured foreground or background subagent in a child session, `question` waits for a user/RPC resolver, LSP tools require `lsp.query` plus configured local servers, and plugin/MCP tools stay behind plugin/MCP permissions. Tool dispatch within a single agent turn remains sequential for replay and audit ordering; the `task` background path is the supported concurrent subagent mechanism, tracked by the backend background job registry.

Headless modes are fail-closed for permission prompts unless an explicit supported read/search policy, such as `--allow read-only`, is supplied. This applies to backend decisions whose action is `ask`; operations allowed directly by the workspace policy do not create a prompt. Skill loading, network access, and MCP access are separate: `--allow read-only` does not allow those prompts, while `--allow-tool skill`, `--allow-tool webfetch`, `--allow-tool websearch`, and `--allow-tool mcp` can auto-allow exact matching prompts for those tool families. Task launch is already prompt-free and audited unless an exact persisted task deny matches; `--allow-tool task` remains accepted for compatibility but is not needed. Only sensitive nested or child actions prompt: foreground child Ask actions use the normal parent permission UI, while background child Ask actions fail closed. In RPC mode, matching prompts are auto-allowed before `permission_requested`; non-matching asks still require `permission_reply`:

```sh
ava --print "inspect this project" --allow read-only
ava --print "read the README" --allow-tool read_file
ava --print "list and search files" --allow-tool list_directory,glob,grep
ava --print "load a listed skill" --allow-tool skill
ava --print "delegate focused exploration"
ava --print "fetch release notes" --allow-tool webfetch
ava --print "search current release notes" --allow-tool websearch
ava --print "use configured plugin command" --allow-tool plugin
ava --rpc --allow read-only
```

`--allow-tool task` remains an accepted compatibility flag but has no task-launch prompt to approve. `--allow-tool plugin` only auto-allows exact plugin model tool launch/call prompts and exact plugin command launch/run prompts. It does not auto-approve plugin proxy file/search/shell/network prompts or passive plugin event hook launch/observe prompts.

Use RPC mode for a long-lived JSONL stdio automation client:

```sh
printf '%s\n' '{"id":"state","type":"get_state"}' | ava --rpc
printf '%s\n' '{"id":"state","type":"get_state"}' | ava --mode rpc
```

Agent-control words are intentionally distinct across TUI, line/headless output, and RPC: **cancel/stop** requests cooperative interruption of the active run and clears queued work; **interrupt** is the user-facing key/action that sends that cancel request; **steer-now** (`/steer` or RPC `steer`) queues guidance for the next safe provider boundary inside the active run; **queue-next** (Alt+Enter or RPC `follow_up`) starts a follow-up prompt only after the active run completes; **restore draft** (`/restore` or Alt+Up) pulls the latest pending queued item back into the composer before delivery; and **resume-later** means exiting and reopening a persisted session with `/resume`, `--continue`, or `--session`. A canceled turn is not automatically resumed; submit a new prompt or resume the session explicitly.

See `docs/rpc-protocol.md` for the normative AVA RPC v1 wire contract, command/event catalogs, correlation rules, and client examples; `docs/headless-protocol.md` covers behavior shared with print/headless modes. AVA RPC is not Pi RPC, JSON-RPC 2.0, or ACP. RPC `prompt` requests can include `attachments:["path/to/image.png"]` for local files or Pi-style `images:[{"type":"image","data":"...","mimeType":"image/png"}]` uploads to import PNG/JPEG/WebP/GIF images into AVA-managed session attachment storage for image-capable models. RPC `export` returns the Markdown session export; `export_html` returns HTML unless `outputPath`/`output_path` is supplied, in which case AVA writes the HTML through the permissioned file path. Dedicated RPC session import/share commands are deferred; local JSONL import is available through slash/line-shell `/import <path.jsonl> --confirm`. RPC `list_commands` and `invoke_command` expose project/global prompt commands, skills, plugin commands, and MCP prompt commands through the shared command registry.

`ava --acp` starts AVA's separate stable ACP v1 JSON-RPC 2.0 stdio endpoint for configured editor and IDE clients. Exact Zed, JetBrains 2026.1+, and CodeCompanion.nvim setup examples, negotiated capabilities, security boundaries, test-only SDK/acpx reproduction, evidence labels, and deferred operations are documented in [`acp.md`](../acp.md), the machine-checked [`acp-support.json`](../acp-support.json), and the [`interop/evidence`](../interop/evidence/README.md) policy. Configuration is not execution evidence: Zed 1.9.0 is manual verified only for the captured 2026-07-14 flows, and JetBrains/CodeCompanion were not run here. ACP does not alter AVA RPC or session storage.

## Current Limits

- Built-in providers are OpenAI, Anthropic, DeepSeek, Gemini, Kimi, Moonshot, OpenRouter, Z.AI Coding Plan (Global), Z.AI Coding Plan (China), xAI, Groq, Cerebras, Together, Fireworks, and Mistral, plus optional user-defined providers from `providers.json` (see [custom-providers.md](custom-providers.md)). OpenAI remains the default production path. Anthropic uses native Messages API support for tools and reasoning; AVA can use existing `ANTHROPIC_API_KEY`, `ANTHROPIC_OAUTH_TOKEN`, or `ANTHROPIC_AUTH_TOKEN` credentials but does not initiate Anthropic interactive OAuth because Anthropic does not document a third-party authorization/device flow for AVA-style clients. Gemini uses native Google Generative AI GenerateContent with API-key auth and currently rejects explicit AVA reasoning options. DeepSeek, Kimi, Moonshot, OpenRouter, and Z.AI use OpenAI-compatible shims with built-in profile tests; DeepSeek maps AVA `high`/`xhigh` reasoning levels to `reasoning_effort=high|max`, parses response `reasoning_content`, and retains native reasoning only for an exact-compatible target; request-time portable projection strips it for incompatible targets. Z.AI Coding Plan profiles send Z.AI `thinking` controls with preserved `reasoning_content`, optional `tool_stream`, and glm-5.2 effort mapping. xAI uses the generic OpenAI Responses adapter (no Codex OAuth); Groq, Cerebras, Together, Fireworks, and Mistral use the generic Chat Completions adapter with offline-only contract coverage — no live qualification was performed for those six. Live credentialed smokes for the original smoke-gated set remain release-validation work.
- Built-in model-visible tools are `read_file`, `list_directory`, `write_file`, `edit_file`, `apply_patch`, `glob`, `grep`, `bash`, `webfetch`, `websearch`, `skill`, `task`, `question`, and capability-gated LSP tools for diagnostics, document symbols, workspace symbols, definitions, and references. LSP remains unavailable without explicit servers or exact owner-controlled global `builtin_servers` opt-in; the sole installed-only `clangd` recipe never installs or discovers workspace-local or hardlinked executables. The installed-only `clangd` integration is the sole automatic LSP recipe; every other server requires explicit configuration behind the existing trust and launch-permission boundary. `task` creates a child session using built-in or configured subagents (`general`, `explore`, or trusted custom Markdown definitions), launches prompt-free and audited unless an exact persisted task deny matches, and returns a child `task_id`; background tasks also include a backend `job_id`. Only sensitive nested or child actions prompt; foreground nested Ask actions use the normal parent permission UI, while background nested Ask actions fail closed. Interactive `/jobs` is the human text control surface over those jobs (see Commands). For Pi muscle memory, `/find` runs the native glob path, `/ls` runs the native directory-list path, and visibility flags accept Pi `find`/`ls` aliases without adding duplicate provider schemas.
- Local plugin and MCP foundations exist for command discovery, plugin diagnostics, plugin prompt/skill resources and commands, MCP stdio tool discovery/calls, MCP read-style resources, and MCP prompts through command-registry entries. The stable local plugin authoring guide lives in `docs/extensions/plugin-system.md`, the MCP user/safety summary lives in `docs/extensions/mcp.md`, the compatibility policy lives in `docs/plugin-compatibility-policy.md`, and a minimal sample lives under `examples/plugins/todo/`; representative golden/audit/failure contract tests now cover the v1 foundation.
- The HTTP transport uses the local `curl` executable.
- The TUI now renders assistant text, lightweight Markdown headings/nested lists with ordered-marker normalization, loose-list continuation indentation, task markers/lazy blockquotes/pipe tables with Pi-style borders, narrow fallback, block spacing around headings/dividers/fenced code, visible HTML-like literal tags, and inline code cells/fenced source, JavaScript/TypeScript, HTML, CSS, YAML, and diff syntax coloring/inline styling/bare web URL and email styling/link fallbacks, OSC 8 hyperlinks on terminals that advertise support, inline thinking blocks, and tool lifecycle updates live. Tool cards show backend-provided truncation, spill, diff metadata, and distinct canceled state when those fields are present; the live runtime event path still has summary-only tool results for some backend producers.
- Permission `ask` decisions open a TUI prompt in interactive mode and fail closed in non-TTY/headless mode unless a supported read/search allow policy is supplied or an RPC client answers `permission_requested` with `permission_reply`. Workspace-policy `allow` decisions can still proceed without a resolver, while policy `deny` decisions are never upgraded by headless flags. File mutation asks include `diff_preview` and `diff_truncated` when the backend can safely provide a unified diff. Successful RPC permission/question replies emit `permission_replied` or `question_replied` events before their in-band response; permission replies may include a bounded `reason` field to explain the resolution. Denied tool results preserve the backend reason, risk, resolution reason, generated permission request id, and follow-up `/permissions audit show <request_id>` plus `/permissions diagnose <request_id>` commands in structured backend details; text print mode writes those details to stderr. The ordinary TUI card and `/copy tool` show the actionable denial reason without mirroring internal permission identity; explicit `/permissions` and `/copy permission` surfaces expose the audit detail. On narrow or `NO_COLOR` terminals, expanded permission cards split decision, risk, request id, reason, command, and audit/diagnose follow-ups into separate text rows instead of relying on color. Session permission decisions can be inspected with `/permissions audit [query]`, grouped with `/permissions audit summary [query]`, drilled into with `/permissions audit show <entry_id|request_id>`, rendered as a Markdown table with `/permissions audit export [query]`, or summarized as denial diagnostics with `/permissions diagnose [query]`. Persistent permission rules are managed with `/permissions list`, `/permissions diagnose`, `/permissions explain <rule_id>`, `/permissions add ...`, and `/permissions remove <rule_id>`; list/receipt/explain surfaces lead with human summaries and display-only ordinals while exact rule ids remain the mutation authority. The TUI command and remembered prompt choices use the same protected rule files as RPC rule commands. Matching persistent rules are checked before interactive TUI prompts. RPC `allow_session` replies create process-local exact-match grants that can be listed with `permission_grants`, revoked with `permission_grant_revoke`, or cleared with `permission_grants_clear`.
- Shared runtime events now include backend-owned compaction, bounded provider/compaction retry, retry countdown ticks, cancel-request, and terminal canceled markers. The TUI renders those as audit/status items instead of inferring lifecycle state from command text; retry and compaction markers show attempt totals, retry delays, and a live countdown audit/status item when the backend emits retry ticks.
- Interactive/TUI mode supports local modals for provider login plus question prompts with single-select, multi-select, custom text, and cancel handling. RPC clients can answer `question_requested` with `question_reply` using `answer`, `selected`, or `selected_options` for multi-select prompts.
