# Backend Capabilities At 1.0 Baseline

This checklist tracks the backend capabilities AVA declares for the 1.0 baseline. `docs/roadmap/backend.md` owns sequencing; this file exists so product docs have one status view. In this file, MVP and 1.0 mean the same capability cut; post-MVP means 1.1 and later. The current backend-only 1.1 candidate list lives in `docs/plans/capabilities-1.1.md`.

Status legend: `Done` means implemented with regression coverage, `Partial` means a foundation exists but 1.0 behavior is incomplete, `Planned` means required or desired work that is not implemented yet, and `Deferred` means outside the 1.0 cut but retained on the 1.1+ roadmap.

| --- | --- | --- | --- |

| Permission decision persistence and session audit export | Done | Phase 1 | Tool permission decisions are written as session audit entries. |
| Atomic file writes for normal write/edit flows | Done | Phase 1 | Existing file tools use temp-file plus rename where practical. |
| Print mode and JSONL RPC MVP | Done | Phase 0/1/2 | Protocol version 1, shared event envelopes, resolver replies, session commands, steering, and follow-up queues are implemented. Live headless smokes verified read/search/webfetch in print mode and write/edit/apply_patch/bash/question through RPC replies. |
| Project/global `AGENTS.md` context loading, prompt commands, and skills | Done | Phase 0/3/6 | `AGENTS.md` loading, project/global prompt commands, skill discovery, and unified command-registry exposure are implemented with focused coverage. |

| Provider-native reasoning storage and replay | Done | Phase 5.5/0.70 | Reasoning blocks, signatures/redacted data, reasoning-control changes, and exact-compatible native replay have inspectable session coverage. Projection does not repair malformed committed v4 output or missing/mismatched required tool-result bindings. |

Request-time target-aware projection preserves exact-compatible native history, strips incompatible private/native reasoning and metadata, continues visible text and complete representable tool pairs, and does not rewrite persisted sessions. Selection can succeed while the next request still fails closed for malformed committed v4 output or a committed v4 function call without its exact bound result. |
| Reasoning/thinking controls | Done | Phase 5.5/0.70 | Reasoning controls are exposed only for models whose metadata declares support and are validated before provider request builders serialize native fields. |
| Anthropic OAuth refresh | Partial | 1.1 candidate | Backend request resolution can use stored/env Anthropic Claude OAuth bearer tokens and refresh stored tokens before use; interactive Anthropic OAuth login and live-smoke validation remain deferred. |

| MCP servers through plugin/runtime safety model | Done | Phase 6 | Stdio MCP tools, read-style resource reads, permission-gated process hosting, discovery failure handling, prompt list/get foundations, focused audit-denial tests, representative golden fixtures, fake-server coverage, and manual headless permission validation exist for the 1.0 stdio MCP slice. |

| Full LSP symbols, definitions, and references | Done | 1.1 candidate | The backend slice includes symbols, definitions, references, pull/publish diagnostics, bounded full-text sync, explicit config, exact global installed-only `clangd`, `lsp.query`, and identity-bound high-risk launch permission. Installed-only `clangd` is the sole automatic LSP recipe; every other server requires explicit configuration. Unsaved-buffer sync remains later work. |
| Image or multimodal support | Done | Post-1.0 / current develop | Image-capable model metadata, session attachment shape, AVA-managed attachment storage, fork/clone copy, request-time model projection, OpenAI/compatible/Anthropic provider payloads, RPC attachment input, and TUI `/attach` plus Ctrl+V clipboard-image workflows are implemented. | Configurable primary agents, task subagents, and background jobs | Done | Post-1.0 / current develop | Configured primary definitions are selected invocation-locally with `--agent`; the native `task` tool, custom subagent discovery, child sessions, automatically allowed/audited task launch, foreground nested Ask UI, fail-closed background nested Ask actions, and `BackgroundJobRegistry` lifecycle/cancel/status API are implemented. Broader task graph UX remains later work. |
