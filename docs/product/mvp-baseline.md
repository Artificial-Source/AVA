# AVA MVP Baseline

This is AVA's current practical capability baseline. The former Pi MVP parity goal is closed; current scope is governed by [product principles](principles.md) and the [release-readiness ledger](release-readiness.md).

Reference repositories are local behavior references only:

- Pi.dev comparison source: `docs/reference-code/pi/`, cloned from `https://github.com/earendil-works/pi.git`. Its coding-agent package is `docs/reference-code/pi/packages/coding-agent/`.
- OpenCode secondary comparison source: `docs/reference-code/opencode/`, cloned from `https://github.com/anomalyco/opencode.git`.

Do not copy reference source code or architecture into AVA. Borrow capability shape only when it satisfies an AVA user need or measurable quality/safety gap, then implement with narrow C++23 modules, explicit permissions, inspectable local files, and backend/frontend boundaries that match `AGENTS.md`.

## Baseline rule

AVA's product principles define the baseline. Pi.dev and OpenCode can supply comparison cases, but neither defines AVA scope or creates a parity obligation. Frozen release work is admitted only by the release ledger's evidence and review rule.

## Current terminal evidence closure

AVA's current terminal baseline includes 23 isolated tmux scenarios (including `mermaid`), bounded tmux-safe OSC52 copy, double/triple-click transcript selection, a transient scrollbar, previous/next user-turn navigation, cursor shape/blink control with nonblocking direct-Alacritty gating, latest-assistant copy on `/copy` or F5 (`app.transcript.copyLatestAssistant`), configurable unbound half-page actions, and the bounded process-only F6 prompt stash. Optional Mermaid handling is disabled by default and projects only completed assistant `mermaid` fences through a bounded application-owned absolute helper; it is literal presentation only and always retains original-fence fallback.

Interactive AVA requires a terminal on both stdin and stdout. Piped or redirected interactive startup is rejected with `--print`/`--rpc` guidance; keyboard TUI coverage is not broad screen-reader certification. Retained non-goals are session-tree transcript/content filters, LaTeX, arbitrary extension-owned renderers, blocking startup probes, and broad screen-reader certification.

Use these status terms consistently:

| Term | Meaning |
| --- | --- |
| Present | Implemented enough for the current AVA MVP target and backed by automated tests, opt-in smokes, or explicit manual evidence. |
| Partial | Useful behavior exists, but the row remains unchecked because important Pi-baseline depth, validation, UX, or release evidence is missing. |
| Deferred | Valid future work, intentionally outside the current MVP slice until a later design or approval gate. |
| Excluded | Not an AVA MVP goal unless the product direction changes. |

The coverage map for checked checklist rows lives in `docs/product/mvp-coverage-ledger.md`. Keep unchecked rows classified as `Partial`, `Deferred`, or `Excluded` in the row text, the MVP gap ledger, or that coverage ledger.

## Historical MVP capability checklist

This checklist preserves the closed MVP capability accounting. It is not a parity backlog or release authorization; current work is admitted through product principles and the release ledger.

Status guide: checked means `Present` for AVA's current MVP target; unchecked means `Partial`, `Deferred`, `Excluded`, or otherwise not yet product-ready.

### Product Shell, CLI, And Modes

- [x] Native local terminal coding agent implemented in C++23.
- [x] Interactive TUI entry point for TTY use. Non-TTY interactive startup is rejected; use print or RPC for scripts and pipes.
- [x] Print mode with `ava --print`/`-p`, text output, JSONL output, and piped stdin prompt input.
- [x] Stdio JSONL RPC mode for long-lived automation clients.
- [x] Session resume by latest workspace session and explicit session id/prefix.
- [x] Direct positional one-shot prompt UX. `ava "prompt"` and multi-token prompt text use the existing print-mode path and exit after one turn.
- [x] Sessionless/ephemeral `--no-session` mode.
- [x] Pi-style text file argument UX. CLI `@file` arguments and editor/TUI `@` references use the bounded permissioned file-reference path; image file arguments remain tracked under attachment import.
- [x] Pi-style session CLI options such as fork-at-start, custom session name, session directory selection, `--session-id`, and `--resume`/`-r` where they fit AVA's storage model.
- [x] CLI compatibility aliases for headless modes and reasoning where useful. AVA accepts Pi-compatible `--mode json` for JSONL print events, `--mode text` for text print mode, `--mode rpc` for stdio RPC, and `--thinking off|<level>` as a startup alias for existing model-validated reasoning selection, while preserving AVA's `--mode build|plan` agent-mode selection.

### Provider, Models, And Auth

- [x] Provider registry with OpenAI, Anthropic, DeepSeek, Gemini, Kimi, Moonshot, and OpenRouter-compatible families.
- [x] Model metadata for capabilities, modalities, context windows, pricing, and reasoning controls.
- [x] API-key auth from secure local storage and provider environment variables.
- [x] OpenAI browser/device/headless OAuth flows.
- [x] Anthropic OAuth token resolution and refresh for stored or environment-provided tokens.
- [ ] Anthropic interactive OAuth setup and live validation. Deferred: official third-party authorization/device endpoints are not documented, so AVA keeps API-key setup plus stored/env OAuth bearer refresh instead of initiating an unsupported flow.
- [ ] Deferred provider breadth beyond current MVP: Copilot, Bedrock, Vertex, Azure, Groq, xAI, Mistral, and other providers need protocol/auth/model metadata/live-smoke design. DeepSeek is implemented through AVA's OpenAI-compatible path with `reasoning_effort` request mapping and request-time portable projection of incompatible `reasoning_content`; Gemini is implemented through native Google Generative AI `generateContent` with API-key auth and explicit reasoning options currently rejected.
- [x] Provider/model listing UX comparable to Pi's model discovery commands. `/providers` lists runtime availability, selectable status, credential source status without secrets, OAuth disposition, endpoints, and compatibility quirks. `/models` and `/model` list provider/model capabilities, custom-model diagnostics, and unregistered-provider warnings; exact `/model` or `/models`, Ctrl+L, and `/settings` open the TUI selector, Ctrl+P cycles to the next configured or scoped enabled model, Shift+Ctrl+P cycles to the previous model when the terminal reports that enhanced key sequence, and `/scoped-models` opens a TUI cycle selector with Pi-style enable/clear/provider/reorder/save action ids. Broader authenticated provider breadth is deferred in the provider-breadth row.
- [ ] Deferred broader custom provider configuration beyond the current compatible-provider path. Current custom model diagnostics cover missing context, modality, API-family, provider/API-family mismatches, unrecognized API families, unsupported provider ids, support-flag, usage/pricing, reasoning-level, and provider-registration metadata; first-class custom provider registration remains deferred pending strict auth/model metadata validation.
- [ ] Deferred per-request or scoped environment override story for provider credentials/config where useful.
- [x] Immediate model switching with request-time portable history projection. Each request builds a copy-only target-aware projection: exact-compatible native history remains native, while incompatible provider-native/private reasoning and metadata are stripped; visible text and complete representable tool pairs continue. Persisted session history is unchanged; provider-native cross-provider reasoning replay is not claimed. The next request remains fail-closed for malformed committed v4 output or a committed v4 function call without its exact bound result; projection does not repair invalid history.

- Remote plugin/package manager, marketplace, git/npm/self-update install, signing/trust, and custom provider plugins; local plugin directory install/remove is the bounded manual plugin path.
- Advanced MCP transports, OAuth, subscriptions, sampling, templates, binary/blob resources, and richer pagination.
- OS/container sandboxing with truthful cross-platform guarantees.
- Remote model catalogs or dynamic provider package loading.

## Explicit Non-MVP From OpenCode

- Desktop app, web app, cloud console, Slack/Discord bots, SaaS sharing, enterprise account flows, telemetry/stats infrastructure, GPU/container orchestration, Storybook, generated public SDKs, and broad deployment automation.
- Dynamic npm plugin loading or AI SDK package importing inside AVA's core runtime.
- In-process native plugin ABI by default; AVA's out-of-process boundary remains the safer default.

## Acceptance Rule

An MVP feature is not done until docs, tests, and failure modes agree:

- C++ implementation has focused tests or a documented smoke path.
- Permission, cancellation, audit, and output bounds are explicit when side effects are possible.
- RPC/headless contracts are documented when automation clients can observe the feature.
- Session replay/export behavior is defined when persistent records are written.
- `git --no-pager diff --check` passes after documentation or code changes.
