# AVA 0.33 Backend Maturity Ledger

AVA 0.33 tracks backend robustness and content-boundary work in small, verifiable slices. Keep this file updated as each slice lands so the release state is visible without reading commit history.

## Ledger Status

0.33 is now a historical backend maturity ledger, not the current release-position label. It remains the detailed slice-by-slice evidence for the jump from the 0.32 TUI baseline to the 0.60 backend platform line and later 1.0 release evidence.

The runtime number was restored to `0.32.0` after the May backend bump. This is not a stable release. The terminal frontend is still in active development. Entries below preserve the phase status captured by this historical ledger.

Milestone status captured by this ledger against `docs/roadmap/backend.md` and `docs/product/backend-capabilities-1.0.md`:

- Phases 0-4 are closed for the approved backend scope: docs reconciliation, baseline hardening, evented runtime/headless protocol, context/session core, and core tool quality.
- Phase 5 is foundation-complete but not release-complete: provider registry/model catalog, provider-neutral auth paths, retry/error normalization, model-change entries, RPC model listing/switching, and the first Anthropic native slices exist, while provider breadth still depends on Phase 5.5.
- Phase 5.5 remains partial: Anthropic native tool/result replay is underway, while thinking/cache-control completeness, provider-switch pruning/translation, Kimi/Moonshot profile validation, OpenAI-compatible shims, retry/idempotency, and real endpoint smokes remain open.
- Phase 6 is active and partial: plugin/MCP process containment, command exposure, MCP prompt discovery, and unified command-registry seams are being wired, but the full stable plugin foundation and docs/samples are not done.
- This ledger does not declare Backend 1.0/MVP complete; it records the backend maturity slices that moved AVA far enough ahead of the old 0.33 label to justify the 0.60 release-position document.

## Scope

- Keep backend events and command results semantic, typed, and layout-free.
- Keep frontend-owned content adaptation separate from terminal drawing.
- Reduce large coordinator files by moving cohesive helpers into narrow modules.
- Strengthen headless CLI/RPC coverage so backend behavior is testable without the TUI.
- Preserve provider, tool, permission, session, and config safety boundaries.

## Non-Goals

- Do not polish or redesign the visual TUI in this release ledger.
- Do not add terminal layout concepts to backend event or command contracts.
- Do not copy reference UI layouts, screens, or code.
